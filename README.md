# Лабораторна робота №10
**Тема:** Створення серверного застосунку на Node.js.

---

## 1. Мета роботи
Ознайомитися з архітектурою та середовищем виконання Node.js. Навчитися ініціалізувати проєкт за допомогою менеджера пакетів `npm`. Опанувати роботу з вбудованими модулями Node.js та створити власний HTTP-сервер для обробки запитів і відправки JSON-даних для взаємодії з Angular-застосунком.

---

## 2. Хід виконання роботи

1. Створено окрему гілку `lab10` у локальному Git-репозиторії `labs`.
2. Створено директорію `lab10` та ініціалізовано новий Node.js-проєкт командою `npm init -y`.
3. Відредаговано конфігураційний файл `package.json`: додано поле `"type": "module"` для підтримки сучасного синтаксису ES-модулів (`import`/`export`), а також налаштовано скрипти запуску `"start": "node server.js"` та `"dev": "node --watch server.js"`.
4. Розроблено власний модуль даних `data.js`, у якому створено та експортовано масив `todos` зі стартовими об'єктами завдань, структура яких відповідає моделі `Todo` з попередньої лабораторної роботи.
5. Реалізовано вебсервер у головному файлі `server.js` на базі вбудованого модуля `http`:
   * налаштовано HTTP-заголовки **CORS** (`Access-Control-Allow-Origin`, `Access-Control-Allow-Methods`, `Access-Control-Allow-Headers`) та обробку попереднього запиту `OPTIONS`, щоб клієнтський застосунок на Angular міг звертатися до API без блокування браузером;
   * реалізовано базову маршрутизацію `GET`-запитів: кореневий маршрут `/` повертає HTML-сторінку з привітанням, маршрут `/api/v1/todoItem` повертає масив завдань у форматі JSON, а для невідомих шляхів повертається статус `404`.
6. Запущено сервер локально командою `npm run dev` та перевірено роботу обох маршрутів у браузері за адресами `http://localhost:3000/` та `http://localhost:3000/api/v1/todoItem`.
7. Виконано злиття гілки `lab10` в основну гілку `main` та завантажено код у віддалений репозиторій GitHub.
8. Розгорнуто серверний застосунок на хмарній платформі **Render** (Web Service із вказанням `Root Directory: lab10` та безкоштовним тарифом `Free`) і перевірено працездатність публічного ендпоінту `/api/v1/todoItem`.
9. Додано посилання на розгорнутий API на сервісі Render у меню головної сторінки проєкту `labs/index.html` та оновлено сайт на GitHub Pages.

### Реалізація HTTP-сервера (`lab10/server.js`)
```javascript
import http from 'http';
import { todos } from './data.js';

const PORT = process.env.PORT || 3000;

const server = http.createServer((req, res) => {
  // 1. Налаштування CORS (щоб Angular міг звертатися до сервера)
  res.setHeader('Access-Control-Allow-Origin', '*');
  res.setHeader('Access-Control-Allow-Methods', 'GET, POST, OPTIONS, PUT, DELETE');
  res.setHeader('Access-Control-Allow-Headers', 'Content-Type');

  // Обробка попереднього (preflight) запиту від браузера
  if (req.method === 'OPTIONS') {
    res.writeHead(204);
    res.end();
    return;
  }

  // 2. Маршрутизація (Routing)
  if (req.url === '/' && req.method === 'GET') {
    res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
    res.end('<h1>Мій перший сервер на Node.js працює!</h1>');
  }
  else if (req.url === '/api/v1/todoItem' && req.method === 'GET') {
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify(todos));
  }
  else {
    res.writeHead(404, { 'Content-Type': 'application/json; charset=utf-8' });
    res.end(JSON.stringify({ message: 'Маршрут не знайдено' }));
  }
});

server.listen(PORT, () => {
  console.log(`Сервер успішно запущено за адресою: http://localhost:${PORT}`);
});
```

## 4. Відповіді на питання вихідного контролю

### 1. У чому полягає основна відмінність виконання JavaScript-коду в браузері та в середовищі Node.js?
У браузері JavaScript виконується в ізольованому середовищі («пісочниці») для взаємодії з вебсторінкою: має доступ до об'єктів `window`, `document` (DOM) та браузерних Web API, але не має прямого доступу до файлової системи чи мережевих портів комп'ютера. У **Node.js** відсутні DOM і `window`, натомість середовище надає глобальний об'єкт `process` і низькорівневий доступ до операційної системи, файлової системи (`fs`), мережі (`http`) та серверних ресурсів.

### 2. Які завдання вирішує менеджер пакетів npm та за що відповідає файл `package.json`?
Менеджер пакетів **npm** автоматизує встановлення, оновлення та видалення сторонніх бібліотек, керує залежностями проєкту та дозволяє запускати командні скрипти. Файл **`package.json`** є маніфестом Node.js-проєкту: він зберігає метадані (назву, версію), налаштування модульної системи (`"type": "module"`), список встановлених бібліотек (`dependencies`) та скрипти запуску в полі `scripts` (наприклад, `start`, `dev`).

### 3. Чим відрізняються вбудовані, власні та сторонні модулі у Node.js? Наведіть приклади.
* **Вбудовані (Core) модулі** постачаються разом із Node.js і не потребують додаткового встановлення (наприклад: `http`, `fs`, `path`);
* **Власні (Local) модулі** створює сам розробник у межах проєкту та підключає за відносним шляхом (наприклад: `./data.js`);
* **Сторонні (Third-party) модулі** розробляються спільнотою, завантажуються з реєстру npm у папку `node_modules` та підключаються за іменем пакета (наприклад: `express`, `mongoose`).

### 4. Який вбудований модуль Node.js використовується для створення веб-сервера?
Для створення HTTP-вебсервера використовується вбудований модуль **`http`** (або **`https`** для захищеного з'єднання), зокрема його метод `http.createServer()`.

### 5. Для чого ми додавали заголовки `Access-Control-Allow-Origin` (CORS) у відповідь сервера? Що сталося б без них під час запиту з Angular?
Заголовки **CORS** (Cross-Origin Resource Sharing) потрібні для того, щоб сервер явно дозволив браузеру передавати відповідь клієнтському застосунку, який працює на іншому домені або порту (Angular працює на порту `4200`, а сервер Node.js — на порту `3000`). Без цих заголовків браузер з міркувань безпеки (**Same-Origin Policy**) заблокував би отримання даних від сервера і вивів би помилку CORS у консоль розробника.

### 6. Як за допомогою об'єкта `req` (Request) визначити, на який URL звернувся користувач та який HTTP-метод він використав?
Адреса (шлях) запиту зберігається у властивості **`req.url`** (наприклад, `'/api/v1/todoItem'`), а тип HTTP-методу — у властивості **`req.method`** (наприклад, `'GET'`, `'POST'`, `'OPTIONS'`).

### 7. Чому для передачі масиву даних `todos` клієнту ми використали метод `JSON.stringify()`?
Мережевий протокол HTTP передає інформацію у вигляді текстового потоку або байтів і не може напряму передати складний масив чи об'єкт JavaScript із пам'яті сервера. Метод **`JSON.stringify()`** серіалізує (перетворює) JS-масив `todos` у валідний текстовий рядок формату JSON, який клієнт (браузер або Angular) зможе коректно прийняти та розпарсити у структуровані дані.
