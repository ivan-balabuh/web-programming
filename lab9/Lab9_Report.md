# Лабораторна робота №9
**Тема:** Створення простого Angular-застосунку ("Todo list").

---

## 1. Мета роботи
Навчитися розробляти SPA з використанням фреймворку Angular. Опанувати компонентну архітектуру (Standalone Components), механізми прив'язки даних, керування потоком виконання у шаблонах, впровадження залежностей (Dependency Injection) та роботу з REST API за допомогою `HttpClient` та бібліотеки RxJS.

2. Ініціалізовано новий Angular-проєкт без SSR, тестування та вкладеного Git-репозиторію командою `ng new lab9 --style=scss --routing=false --ssr=false --zoneless --skip-tests --skip-git --ai-config=none`.
3. Описано інтерфейс моделі даних `Todo` у файлі `src/app/models/todo.model.ts` та задано власний номер студента за журналом (`USER_ID`) у компоненті `src/app/app.ts`.
4. Налаштовано глобальний провайдер `provideHttpClient()` у файлі `src/app/app.config.ts` для виконання HTTP-запитів у застосунку.
5. Згенеровано сервіс `TodoService` командою `ng generate service services/todo --type=service` та виконано завдання роботи:
   * **Завдання 1 (`src/app/services/todo.service.ts`):** реалізовано метод `update(id: string, data: Partial<Todo>): Observable<Todo>`, який відправляє `PUT`-запит на сервер за адресою `${this.apiUrl}/${id}` для редагування завдання та зміни статусу виконання;

6. Реалізовано реактивний стан компонента `App` за допомогою сигналів (`signal()`), налаштовано двосторонню прив'язку даних `[(ngModel)]` із модулем `FormsModule`, блоки керування потоком `@if` та `@for` у шаблоні `src/app/app.html`, а також глобальні стилі у `src/styles.scss`.
7. Запущено локальний сервер розробки (`ng serve --open`) та протестовано створення, відображення, зміну статусу виконання, редагування та видалення завдань.
8. Виконано продакшн-збірку командою `ng build --base-href ./`, прибрано рядок `/dist` із `lab9/.gitignore`, додано посилання на роботу в `labs/index.html`, виконано злиття гілки `lab9` з `main` та завантажено зміни на GitHub Pages.

## 3. Лістинг коду (TypeScript)

### Модель даних (`src/app/models/todo.model.ts`)
```typescript
export interface Todo {
  id?: string;
  userId: number;
  title: string;
  description: string;
  tag: string;
  deadline: string;
  createdAt?: number;
  isDone: boolean;
}
```

### Конфігурація провайдерів (`src/app/app.config.ts`)
```typescript
import { ApplicationConfig, provideBrowserGlobalErrorListeners } from '@angular/core';
import { provideHttpClient } from '@angular/common/http';

export const appConfig: ApplicationConfig = {
  providers: [provideHttpClient(), provideBrowserGlobalErrorListeners()],
};
```

### Реалізація сервісу API (`src/app/services/todo.service.ts`)
```typescript
import { Injectable, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';
import { Todo } from '../models/todo.model';

@Injectable({
  providedIn: 'root'
})
export class TodoService {
  private http = inject(HttpClient);
  private apiUrl = "https://69b11abdadac80b427c3fff2.mockapi.io/api/v1/todoItem";

  getAll(): Observable<Todo[]> {
    return this.http.get<Todo[]>(this.apiUrl);
  }

  add(todo: Todo): Observable<Todo> {
    return this.http.post<Todo>(this.apiUrl, todo);
  }

  // Завдання 1 — оновлення запису на сервері (PUT)
  update(id: string, data: Partial<Todo>): Observable<Todo> {
    return this.http.put<Todo>(`${this.apiUrl}/${id}`, data);
  }

  // Завдання 2 — видалення запису із сервера (DELETE)
  remove(id: string): Observable<void> {
    return this.http.delete<void>(`${this.apiUrl}/${id}`);
  }
}
```

## 4. Відповіді на питання вихідного контролю

### 1. У чому полягає відмінність SPA-застосунку від класичного веб-сайту з точки зору завантаження сторінок?
Класичний багатосторінковий сайт при кожному переході або дії відправляє запит на сервер і завантажує нову HTML-сторінку цілком із повним перезавантаженням вікна браузера. SPA (Single Page Application) завантажує лише одну базову HTML-сторінку (`index.html`), а подальше оновлення контенту та перемикання станів інтерфейсу відбувається динамічно на стороні клієнта через JavaScript без перезавантаження сторінки.

### 2. З яких основних елементів складається Angular-компонент і яка роль кожного з них?
Angular-компонент складається з трьох основних частин:
* **Клас (TypeScript)** — містить дані (стан, властивості, сигнали) та бізнес-логіку (методи обробки подій);
* **Шаблон (HTML)** — визначає структуру та візуальне представлення елементів інтерфейсу;
* **Стилі (CSS/SCSS)** — інкапсульовані правила оформлення, які застосовуються виключно до цього компонента.

### 3. Що таке Standalone Components (автономні компоненти) і за допомогою якого масиву у декораторі `@Component` до них підключаються залежності?
**Standalone Components** — це самодостатні компоненти Angular, які працюють без проміжних модулів `NgModule` (у сучасних версіях Angular використовуються за замовчуванням). Усі необхідні для роботи компонента залежності (інші компоненти, директиви або модулі на кшталт `FormsModule`) підключаються безпосередньо у масиві **`imports`** декоратора `@Component`.

### 4. Що таке Dependency Injection і як функція `inject()` використовується для отримання доступу до сервісу `TodoService` у компоненті?
**Dependency Injection (впровадження залежностей)** — це патерн проєктування, за якого клас отримує готові екземпляри потрібних йому сервісів із контейнера фреймворку, а не створює їх самостійно через `new`. У компоненті `App` доступ до сервісу отримується декларативно за допомогою функції `inject()`:
```typescript
private todoService = inject(TodoService);
```

### 5. Для чого у шаблонах Angular використовуються конструкції керування потоком `@for` та `@if`?
Вбудовані блоки керування потоком (Control Flow) відповідають за динамічний рендеринг HTML-розмітки:
* **`@for`** — ітерує колекцію даних (масив або сигнал масиву) та створює блок розмітки для кожного елемента списку;
* **`@if` (та `@else`)** — виконує умовний рендеринг фрагментів інтерфейсу (наприклад, показ індикатора завантаження `⏳ Завантаження даних з сервера...` лише тоді, коли `isLoading()` повертає `true`).

### 6. Яку роль відіграє параметр `track` у циклі `@for` і чому він є обов'язковим?
Параметр **`track`** (наприклад, `track task.id`) вказує Angular унікальний ідентифікатор кожного елемента колекції. Він є обов'язковим для оптимізації продуктивності: коли масив оновлюється, Angular за ключем `track` визначає, які саме елементи додалися, змінилися чи видалилися, і перемальовує лише їх, замість повного перестворення всіх DOM-вузлів списку.

### 7. Як працює двостороння прив'язка даних (`[(ngModel)]`) під час заповнення форми? З яким модулем її необхідно імпортувати?
Синтаксис **`[(ngModel)]`** поєднує прив'язку властивості `[ngModel]` та прив'язку події `(ngModelChange)`: коли користувач вводить текст у поле форми, значення відповідного сигналу або змінної в класі миттєво оновлюється, а при програмній зміні значення в коді (наприклад, у `editTask()` чи `resetForm()`) автоматично оновлюється вміст поля в інтерфейсі. Для роботи `[(ngModel)]` необхідно імпортувати **`FormsModule`** із пакета `@angular/forms`.

### 8. Чим відрізняється підхід з використанням Angular `HttpClient` від роботи зі стандартним JavaScript API `fetch`?
* `HttpClient` інтегрується в систему Dependency Injection Angular та повертає потік даних **`Observable`** (з бібліотеки RxJS), який активується після виклику `.subscribe()` і підтримує оператори трансформації потоків, тоді як `fetch` повертає **`Promise`**.
* `HttpClient` автоматично серіалізує тіло запиту в JSON, десеріалізує відповідь сервера з підтримкою узагальнених типів TypeScript (наприклад, `this.http.get<Todo[]>()`) і вважає HTTP-статуси `4xx`/`5xx` помилками потоку, тоді як у `fetch` потрібно вручну викликати `response.json()`, додавати заголовки `Content-Type` та перевіряти `response.ok`.

### 9. Для чого виконується команда `ng build`, чому для деплою застосунку необхідно редагувати файл `.gitignore` та для чого при публікації на GitHub Pages використовується параметр `--base-href ./`?
* Команда **`ng build`** компілює TypeScript і SCSS, оптимізує та мініфікує код застосунку у статичні файли (`index.html`, `.js`, `.css`) в директорії `dist/lab9/browser/`.
* У файлі **`.gitignore`** за замовчуванням вказано `/dist`, через що Git ігнорує зібрані файли; видалення або коментування цього рядка дозволяє закомітити збірку в репозиторій для відображення на хостингу.
* Параметр **`--base-href ./`** встановлює відносний базовий шлях у тезі `<base href="./">`, оскільки на GitHub Pages проєкт відкривається з підкаталогу (`/<репозиторій>/lab9/dist/lab9/browser/`), а не з кореня домену — без цього браузер шукав би скрипти в корені домену й отримував помилку 404.

### 10. Що таке `signal` в Angular? Як створити сигнал, прочитати та змінити його значення і чому після зміни сигналу не потрібно вручну оновлювати інтерфейс?
**`signal`** — це реактивна обгортка навколо значення, яка відстежує, де саме це значення використовується в шаблоні, та автоматично сповіщає Angular про його зміну:
* **Створення:** `todos = signal<Todo[]>([]);`
* **Читання:** виклик сигналу як функції з дужками — `this.todos()` у класі або `{{ title() }}` у шаблоні;
* **Зміна значення:** через `.set(newValue)` для повної заміни або `.update(fn)` для обчислення нового стану на основі попереднього (наприклад, `this.todos.update(list => [newTask, ...list])`).

Оскільки сигнал сам зберігає зв'язок із місцями свого використання у DOM, після зміни його значення Angular точково оновлює лише пов'язані елементи інтерфейсу без ручного запуску перевірки змін (що особливо важливо у zoneless-режимі).

## 5. Висновок
Під час виконання лабораторної роботи №9 було розроблено односторінковий веб-застосунок (SPA) «Todo list» на базі фреймворку Angular 21. На практиці опановано побудову автономних компонентів (Standalone Components), управління станом інтерфейсу за допомогою реактивних сигналів (`signal`), двосторонню прив'язку форм `[(ngModel)]`, впровадження залежностей через `inject()`, а також взаємодію з REST API методами `GET`, `POST`, `PUT` і `DELETE` за допомогою сервісу `HttpClient` та потоків RxJS.
